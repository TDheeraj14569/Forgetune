### 2.2 Analysis of Speedups
- **Small Batch & Edge Inference Dominance:** At batch sizes $B \in [1, 16]$, ForgeTune substantially outperforms PyTorch CPU eager execution because PyTorch incurs framework dispatch overhead of 30–50 μs per operator call. ForgeTune compiles the entire graph into a single compiled C++ shared library with fused operator loops, delivering genuine E2E speedups up to **8.02x** (Model C, $B=4$).
- **Autotuner Baseline Fallback & Tie-Breaking:** For Models A and B, in-kernel differences across candidate variants are within the $<5\%$ noise window; the autotuner strictly retains `baseline_naive` (1.00x ratio), avoiding overfitting to timer jitter.
- **Fusion & Branchless Padded Conv2D Optimization:** In Model C, branchless padded row buffering, 4x channel unrolling in registers, direct in-register ReLU epilogue, and loop tiling in `src/codegen.cpp` improved native Conv2D performance significantly, reducing in-kernel latency at $B=64$ to **375.29 μs** (1.25x kernel speedup over ForgeTune baseline of 469.06 μs). In 30 independent sample batches, tuned native kernel median latency is **419.92 μs** (IQR 19.75 μs), faster than single-threaded PyTorch E2E (**453.50 μs**).
- **End-to-End Boundary Analysis:** At Model C batch 64 across 30 independent sample batches, ForgeTune Python E2E median latency is **453.12 μs** (IQR 3.70 μs), faster than single-threaded PyTorch E2E (**453.50 μs**, IQR 22.78 μs). Pure single-threaded native C++ execution inside the shared library achieves **419.92 μs**.
