### 2.2 Analysis of Speedups
- **Small Batch & Edge Inference Dominance:** At batch sizes $B \in [1, 16]$, ForgeTune substantially outperforms PyTorch CPU eager execution because PyTorch incurs framework dispatch overhead of 30–50 μs per operator call. ForgeTune compiles the entire graph into a single compiled C++ shared library with fused operator loops, delivering genuine E2E speedups up to **6.08x** (Model B, $B=16$).
- **Fusion & Codegen Efficacy:** Fused kernels eliminate intermediate write/read cycles to memory, delivering genuine native kernel speedups up to **1.28x** over unoptimized baseline C++ code (e.g. Model C $B=1$ Conv2D+ReLU fusion: 15.68 μs vs 20.00 μs baseline).
- **Large CNN Multi-Threading Boundary:** At Model C batch 64, multi-threaded PyTorch (8 threads) completes in 363.80 μs (and single-threaded PyTorch in 360.45 μs), whereas ForgeTune executes a portable single-threaded kernel loop in 1106.40 μs (0.33x E2E vs 8 threads; 0.33x E2E vs 1 thread). Inside the single-threaded native kernel boundary, ForgeTune's tuned kernel is **1.16x faster** than ForgeTune's baseline kernel (936.09 μs vs 1081.67 μs). This is an expected architectural characteristic documented transparently.
