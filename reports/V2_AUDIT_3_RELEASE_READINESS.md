### 2.2 Analysis of Speedups
- **Small Batch & Edge Inference Dominance:** At batch sizes $B \in [1, 16]$, ForgeTune substantially outperforms PyTorch CPU eager execution because PyTorch incurs framework dispatch overhead of 30–50 μs per operator call. ForgeTune compiles the entire graph into a single compiled C++ shared library with fused operator loops, delivering genuine E2E speedups up to **5.88x**.
- **Fusion & Codegen Efficacy:** Fused kernels eliminate intermediate write/read cycles to memory, delivering genuine native kernel speedups up to **1.79x** over unoptimized baseline C++ code (e.g. Model C B=1 Conv2D+ReLU fusion: 18.59 μs vs 33.32 μs baseline).
- **Large CNN Multi-Threading Boundary:** At Model C batch 64, multi-threaded PyTorch (8 threads) completes in 426.05 μs (and single-threaded PyTorch in 488.35 μs), whereas ForgeTune executes a portable single-threaded kernel loop in 1118.00 μs (0.38x E2E vs 8th; 0.44x E2E vs 1th). Inside the single-threaded native kernel boundary, ForgeTune's tuned kernel is **1.15x faster** than ForgeTune's baseline kernel (978.26 μs vs 1121.20 μs). This is an expected architectural characteristic documented transparently.
