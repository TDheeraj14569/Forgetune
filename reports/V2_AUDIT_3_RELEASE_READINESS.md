### 2.2 Analysis of Speedups
- **Small Batch & Edge Inference Dominance:** At batch sizes $B \in [1, 16]$, ForgeTune substantially outperforms PyTorch CPU eager execution because PyTorch incurs framework dispatch overhead of 30–50 μs per operator call. ForgeTune compiles the entire graph into a single compiled C++ shared library with fused operator loops, delivering genuine E2E speedups up to **6.23x** (Model A, $B=4$).
- **Autotuner Baseline Fallback & Tie-Breaking:** For Models A and B, in-kernel differences across all candidate variants are within the $<5\%$ noise window; the autotuner strictly retains `baseline_naive` (1.00x ratio), avoiding overfitting to timer jitter.
- **Fusion & Codegen Efficacy:** In Model C, compiler loop hoisting, register caching of filter weights, and contiguous spatial output accumulation in `src/codegen.cpp` improved native Conv2D performance by **1.72x** (reducing in-kernel latency at $B=64$ from 936.1 μs to 545.50 μs, and E2E latency from 1,106.4 μs to 597.30 μs). The autotuner selected `tiled_16`, delivering consistent **1.05x to 1.19x** native in-kernel speedups over the baseline C++ kernel across all batch sizes.
- **Large CNN Multi-Threading Boundary:** At Model C batch 64, multi-threaded PyTorch with oneDNN AVX2 (8 threads) completes in 504.45 μs (and single-threaded PyTorch in 449.55 μs), whereas ForgeTune executes a portable single-threaded kernel loop in 597.30 μs (0.84x E2E vs 8 threads; 0.75x E2E vs 1 thread). Inside the single-threaded native kernel boundary, ForgeTune's tuned kernel is **1.19x faster** than ForgeTune's baseline kernel (545.50 μs vs 650.79 μs). This is an expected architectural characteristic documented transparently.
